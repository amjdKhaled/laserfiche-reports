# نقل تقارير ليزرفيش إلى Windows آخر

## على الجهاز الأول (مرة واحدة)

من مصدر المشروع شغّل:

```powershell
.\deployment\windows\build-package.ps1
```

يحتاج البناء .NET 8 SDK. ينتج ملف ZIP داخل `artifacts` يحتوي التطبيق مع .NET
ومخطط الذكاء. الحزمة لا تحتوي كلمات المرور أو قاعدة البيانات أو مستودع Laserfiche.

## على الجهاز الثاني

1. ثبّت **Python 3.11 x64** مع Python Launcher، وثبّت **Ollama** بإصدار حديث.
2. فك ZIP كاملًا في مجلد، ثم افتح `Install.cmd`.
3. التثبيت ينزّل المكتبات و`gpt-oss:20b` ويختبر تحميله وإخراج JSON. تحتاج إنترنت
   لهذه الخطوة. حجم النموذج نحو 14GB؛ احتفظ بمساحة وذاكرة تكفيان للنموذج والسياق.
4. يسألك المثبت عن عنوان Laserfiche في أول تثبيت. `localhost` مناسب فقط إن كان
   Laserfiche مثبتًا على **الجهاز الثاني نفسه**؛ وإلا استخدم اسم/عنوان خادم Laserfiche
   القابل للوصول وشهادة HTTPS موثوقة. يحفظه في
   `%LOCALAPPDATA%\LaserficheReports\web\appsettings.Local.json`؛ عدّل هذا الملف
   إذا تغير الخادم أو مسار API. أبق `/LFRepositoryAPI` إذا لم يتغير.
5. سجّل الدخول واختر المستودع. لا تحتاج تعديل كود API ولا Visual Studio أو .NET SDK
   على الجهاز الثاني. يبدأ التطبيق مع دخول نفس مستخدم Windows.
6. اختبر الأسئلة الثلاثة المقترحة ثم سؤالًا تعرف نتائجه من Laserfiche، وقارن العدد
   والحقول. نجاح تحميل النموذج ليس إثباتًا لصحة جميع أسئلتك أو صلاحيات حسابك.

تعمل تقارير Metadata مباشرة من Laserfiche. إذا تستخدم فهرسة المحتوى أيضًا فاضبط
Supabase ونموذج embeddings والخدمات الاختيارية المتصلة؛ الحزمة لا تنقلها.

للتحديث شغّل `unregister.ps1` في الحزمة السابقة لإيقاف التطبيق مع حفظ إعداداته،
ثم ثبّت الحزمة الجديدة. لا تنسخ مجلد python من جهاز لآخر؛ المثبت يعيد إنشاءه.

اختصار سطح المكتب يفتح `http://127.0.0.1:5187`. لا يستخدم النقل ملفات Laserfiche
ولا يحذفها. إذا سينتقل **خادم Laserfiche نفسه** فهذا يحتاج عملية backup/restore
منفصلة، ولا يكفي نقل تطبيق التقارير.

## فحص الذكاء قبل النشر

بعد التثبيت، من المجلد المثبت:

```powershell
& "$env:LOCALAPPDATA\LaserficheReports\python\Scripts\python.exe" "$env:LOCALAPPDATA\LaserficheReports\graph\release_check.py" --output "$env:LOCALAPPDATA\LaserficheReports\logs\release-check.json"
```

يشغّل الأسئلة المقترحة وحالات أخطاء الحقول والتواريخ عبر النموذج الحقيقي في
`/route`، دون تعديل المستودع. يجب نجاحها جميعًا. هذا فحص خطط باستخدام كتالوج
اختبار، ويظل فحص النتائج الفعلية مع خادمك وحسابك مطلوبًا.
