# تقرير تنفيذ Laserfiche-first

## النتيجة وحدود التحقق

تم تعديل مشروع Laserfiche Reports الموجود، دون تعديل مشروع Dashboard أو نسخ كود منه. المسار النشط لا يتصل بـSupabase أو OCR أو embeddings أو RAG أو LangGraph. البيانات الأصلية والجداول القديمة لم تُحذف.

العمل قابل للمراجعة على الفرع `refactor/laserfiche-first-live-data`. هذه ليست شهادة اختبار على جهاز المستخدم: خادم Laserfiche الحقيقي ونماذج Ollama/LM Studio المثبتة عنده غير متاحة في بيئة التنفيذ.

## أسباب التعليق والبطء التي أثبتها الكود والاختبار

- كان middleware يقفل جميع طلبات `/api` لنفس جلسة المتصفح، ويحتفظ بالقفل طوال السؤال أو فحص الخدمة. فحص اتصال بطيء كان يؤخر حتى `/api/app/status`.
- كانت قائمة الوثائق تستعلم من PostgreSQL وتتحقق من صلاحية كل وثيقة بطلب منفصل. الأسئلة غير المصنفة كانت تطلب embeddings ثم PostgreSQL ثم LangGraph/AI.
- كانت تقارير العد والحقول المباشرة في الخدمة القديمة تجتاز شجرة المجلدات ثم تطلب تفاصيل/حقول الوثائق، أي عدة طلبات لكل وثيقة.
- كان ترقيم المجلدات يحمل جميع الأبناء ثم يقسمهم محليًا. ترقيم البحث كان يعيد `PageNumber=1` لبعض الصفحات ويخلط العدد الحقيقي بعداد مؤقت عند غياب العدد.
- لم أجد مسحًا شاملًا تلقائيًا عند بدء عملية الخادم. المسح المتكرر كان في التقارير القديمة وفي زر الفهرسة اليدوي. لا توجد قياسات تثبت أن بدء عملية الخادم كان ينتظر Supabase؛ الاعتماد المثبت كان في وظائف القائمة والأسئلة.

## المسار الجديد

سؤال المستخدم → QuestionRouter أو JSON صادر عن Local AI → Validate → LaserficheToolExecutor → Repository API → حسابات وتقرير موثّق بالكود → تحليل محلي اختياري يبث تدريجيًا.

الأسئلة البسيطة لا تحتاج نموذج AI. الأسئلة العامة تستخدم النموذج لاختيار نوع الطلب، مع قائمة أسماء الحقول المتاحة، ثم يتحقق الخادم من الاختيار. التعليق على التقرير يستخدم بيانات الأدوات فقط. الجدول والأعداد الأساسية تُكتب بالكود؛ تعليق النموذج يظل تفسيرًا لغويًا ينبغي مراجعته عند الاعتماد عليه.

## الأدوات والتوجيه

| الطلب | التنفيذ |
| --- | --- |
| عدد الوثائق/المجلدات/الإدخالات | بحث بنوع الإدخال وطلب `$count`؛ تعداد صفحات النتائج فقط عند غياب عدد موثوق |
| بحث باسم وثيقة أو بقيمة حقل أو قالب | صيغة بحث يولدها backend من مدخلات معتمدة، مع نوع الإدخال والصفحة والترتيب |
| بيانات وثيقة | تفاصيل الإدخال ثم حقوله الحالية، دون محتوى الصفحات |
| محتويات مجلد | تحديد ID أو حل اسم فريد، ثم صفحة الأبناء المباشرين فقط |
| قوالب المستودع | TemplateDefinitions الحالية |
| معلومات المستودع | خدمة Repository API الموجودة |
| الإنشاء/التعديل ضمن تواريخ | تواريخ منظمة وصيغة بحث بالتنسيق المحلي المهيأ |
| تقرير بحسب الإدارة/الحالة | قراءة جميع صفحات نتائج البحث مع إسقاط الحقول وتجميعها بالكود، دون طلب حقول مستقل لكل وثيقة |
| سؤال يحتاج صورة/محتوى صفحات | توضيح أن الوظيفة غير متاحة حاليًا |

الاسم الموحد للأداة في JSON هو `intent`؛ لا توجد واجهات HTTP عشوائية يختارها النموذج. أنواع الطلبات هي `count`, `search`, `metadata`, `folder`, `templates`, `repository`, `report`, `unsupported`.

## التحقق وصحة البيانات

- التحقق من نوع الطلب والإدخال والمعامل والأرقام والصفحة وحجمها والترتيب والتواريخ وطول النص.
- رفض رموز صيغة البحث والـwildcards في قيم المستخدم/النموذج؛ صيغة LF يولدها الخادم فقط.
- مطابقة أسماء الحقول والقوالب مع تعريفات المستودع الحالي، ورفض الأسماء الملتبسة.
- JSON النموذج لا يقبل خصائص زائدة مثل URL أو repository أو rawQuery.
- دعم المقارنة `equals` فقط في هذه المرحلة؛ المقارنات المركبة أو غير المدعومة تحتاج تحديدًا أوضح.
- القيمة العربية نفسها لا تُصحح تخمينيًا. تطبيع أسماء الحقول يساعد على تحديد التعريف؛ القيمة تُرسل كما طلبها المستخدم.
- عند متابعة النتائج، تُحفظ شروط الطلب السابق ويُعاد السؤال إلى المصدر مباشرة.
- الأعداد تعتمد على صلاحيات الحساب الحالي، ولا تدعي تعداد الوثائق المحجوبة عنه.
- لا تُعرض نتائج عينة على أنها المستودع كاملًا. عند غياب `$count` لا يُقدّر العدد.

## الصفحات والتقارير الكبيرة

طلبات البحث والمجلدات تستخدم `$skip/$top/$count` على الخادم. القوائم تعرض 50 إدخالًا، والمحاثة تعرض افتراضيًا 20، ويمكن التنقل بين صفحات النتائج. إذا غاب العدد وكان حجم الصفحة كاملًا، يُفحص وجود صفحة أخرى بدل افتراض أن العدد نهائي.

التقارير تقرأ النتائج على صفحات 100 إدخال، وتحتفظ بصفحة معاينة صغيرة وتجميع محسوب، مع حد افتراضي 100,000 سجل. إذا تكرر ID، تغير العدد خلال التقرير، غاب إسقاط الحقول، أو بُلغ الحد، يُرفض إصدار إحصاء كامل مضلل. تنزيل التقرير يحتوي التقرير المعروض والمعاينة؛ ليس تصديرًا شاملًا لكل الصفوف.

لا توجد ضمانة transaction snapshot أثناء تعديلات متزامنة في المستودع؛ قد تتغير قيم مع ثبات العدد. يمكن إعادة التقرير للحصول على قراءة أحدث. تجميع الحقول متعددة القيم غير مدعوم بهذه المرحلة ويُرفض صراحة.

## الجلسات والتبديل والإلغاء

قفل الجلسة يُستخدم فقط لقراءة snapshot قصيرة أو لتسجيل الدخول/الخروج. الطلبات العادية تنفذ بالتوازي بعد ذلك. كل طلب يحمل هوية المستودع وجيل الجلسة. المخالفة تُرجع 409. تغيير الجلسة يلغي عمل الجيل السابق في الخادم، والمتصفح يلغي الطلبات القديمة ويتجاهل نتائجها. رموز الدخول تستخدم cache منفصلًا ومزامنة single-flight الموجودة سابقًا.

واجهة الدخول والشعار والألوان والتخطيط والمحادثات محفوظة. أُزيلت أدوات الفهرسة من الصفحة. حالات الاتصال مستقلة، والتحميل داخل الجزء المتأثر، والتنقل متاح أثناء التحميل. أُزيل زر إلغاء السؤال بطلب المستخدم؛ يبقى إلغاء الطلبات القديمة عند تبديل المستودع.

## المهل والتعافي والأخطاء والسجلات

- Health افتراضيًا 8 ثوانٍ، استعلامات Laserfiche 120 ثانية للعملية، وHttpClient 45 ثانية للطلب. مهلة AI منفصلة وقابلة للضبط، مع سقف محدود.
- Cancellation ينتقل من HTTP إلى أدوات Laserfiche والـAI. لا يوجد scan خلفي جديد ولا مزامنة بيانات.
- إعادة محاولة محدودة لقراءات GET عند 502/503/504 أو فشل الاتصال، بتأخير وجِتر. لا يُعاد POST عشوائيًا، ولا تُعاد أخطاء 401/403/404 كأخطاء مؤقتة. إعادة تجديد token الحالية محدودة مرة واحدة.
- Circuit breaker لكل خادم يفتح بعد 3 إخفاقات مؤقتة لمدة 15 ثانية، ثم يسمح بطلب تعافٍ واحد. الإلغاء لا يُعامل كسبب لإعادة محاولة لا نهائية.
- الأخطاء تعاد بصيغة problem JSON عربية مع correlation ID؛ التفاصيل التقنية لا تظهر للعميل كـstack trace.
- السجلات تدور يوميًا وعند 10 MB مع الاحتفاظ بـ14 ملفًا، داخل بيانات المستخدم المحلي. أزيل تسجيل أجسام ردود Laserfiche. السجلات لا تخزن نصوص وثائق كاملة.
- `/health` يتحقق من جاهزية العملية فقط. فحص AI يستعلم عن models/tags دون توليد إجابة أو embedding.
- SSE يبث مراحل العمل ثم جواب النموذج مباشرة. تُرسل مصادر الوثائق وبيانات الصفحات بصورة مستقلة. عند تعذر النموذج قبل توليد نص، تظهر البيانات الموثقة مع رسالة واضحة بأن جواب AI لم يتولد.

## إعدادات التشغيل

انسخ `appsettings.Local.example.json` إلى `appsettings.Local.json` في مجلد Web. عيّن خادم Laserfiche، والمستودع، و`LocalAI:ChatModel` إلى اسم نموذج محادثة مثبت فعليًا. لا يلزم Supabase أو graph server.

Ollama: `Provider=Ollama`, `BaseUrl=http://localhost:11434`.
LM Studio: `Provider=LMStudio` أو `OpenAICompatible` مع عنوان الخادم المحلي دون لاحقة `/v1`.

`Reports:TimeZone=Asia/Riyadh` يحدد اليوم والأسبوع؛ `Reports:DateFormat` يجب أن يتوافق مع locale البحث على خادم Laserfiche. مثال: `MM/dd/yyyy`.

الـfeatures القديمة غير مستخدمة في الويب الحالي. ملفاتها ومهاجرات DB موجودة كمرجع/للعودة المدروسة؛ مجرد تغيير feature flag لا يعيد واجهاتها القديمة تلقائيًا.

## قياسات الأداء

قياسات fixtures محلية، وليست خادم Laserfiche حقيقيًا؛ لا يجوز تعميمها على مستودع كبير.

| القياس | قبل | بعد |

| طلب app/status خلف فحص LF بطيء، الوسيط من 3 محاولات | 906 ms | 2.66 ms |
| startup في smoke مستقل | — | 428 ms |
| app/status أثناء سؤال بطيء | — | 5.95 ms |
| زمن الأسئلة في fixture، P50 | غير مقاس | 13.8 ms |

التحسن المثبت هو إزالة الانتظار خلف طلب آخر، وليس تقليل وقت بدء العملية. المقارنة الأولى تستخدم نفس fixture مع تأخير ثانية لفحص LF. قياسات P50/P95 تجريبية قليلة العينات؛ يسجل النظام durations لتجميع إحصاءات فعلية على الجهاز لاحقًا.

## المشاكل/الحدود المتبقية فعليًا

عند استكمال العمل، أُصلح الانتقال بين صفحات القوالب ومحتويات المجلد بحيث يحتفظ بنوع الأداة الأصلية، وتُرفض قائمة تجميع null أو أسماء حقول فارغة كخطأ تحقق بدل خطأ خادم. أضيفت خمس حالات اختبار لهذه التصحيحات. أعيد البناء بنجاح عبر `dotnet build --no-restore -m:1 -nr:false -p:UseSharedCompilation=false`؛ بقيت تحذيرات توافق صور Windows وتحذير assertion قديم. أعيد `dotnet test` وتعطل مشغّل VSTest قبل الاختبارات بنفس خطأ البيئة، لذلك لا تُحسب هذه العملية ناجحة. CI على Windows مفعّل أيضًا عند رفع فرع التعديلات.

تم التحقق من VSTest في CI/Windows بنجاح. الخادم الحقيقي، النموذج الحقيقي، والمتصفح الفعلي لم تختبر هنا. دعم المقارنات مركب/متعدد القيم، تصدير كل صفوف التقرير، ومحتوى الصور والصفحات خارج النسخة الحالية. اختيار نموذج محادثة مثبت وتوافق locale التاريخ شرطان للأسئلة العامة والتاريخية. لا يوجد cache محلي لنسخة الوثائق ولا فهرسة يدوية مطلوبة للبيانات الوصفية.

## التحقق النهائي على Windows

نجحت جميع مهام [GitHub Actions رقم 52](https://github.com/amjdKhaled/laserfiche-reports/actions/runs/37291966484) على commit `92ee64405050915b3bc2bac76cd8888279294921`: .NET، الواجهة، Python، واختبار قاعدة البيانات التاريخي المعزول. نجح restore/build/test المعتاد، ثم اختبار التشغيل بالأسئلة الـ12 وتغييرات البيانات وSSE وتعطل الخدمات. أُصلح اختبار التشغيل ليطلب منفذًا مستقلاً متاحًا بدل افتراض توفر المنفذ المجاور، ولطباعة العربية بترميز UTF-8.

قياسات fixture على Windows: ظهور الواجهة 1203 ms، وطلب الحالة أثناء سؤال بطيء 16 ms، وP50 للأسئلة 16 ms، وP95 للعينة 62 ms. هذه قياسات لخدمات تجريبية ولا تصف أداء خادم المستخدم. اختبارات الخادم الحقيقي والنموذج الحقيقي والمتصفح البصري تظل مطلوبة.

## تحديث 6 أكتوبر: جواب AI لكل سؤال وتشغيل Windows

كل جواب في المحادثة، بما فيه العد والبحث والبيانات الوصفية، يمر الآن إلى نموذج المحادثة لصياغة جواب عربي بعد الحصول على النتيجة الموثقة من Laserfiche. تُحفظ الجداول والأعداد المحسوبة في backend. فشل AI لا يمحو البيانات التي وصلت؛ تُعرض رسالة تعذر الصياغة. تحليل محتوى الصور والصفحات يبقى خارج المرحلة الحالية، ويشرح AI هذا القيد دون اختراع نص الوثيقة.

عند غياب ChatModel تُقرأ النماذج المثبتة من خادم AI ويُختار نموذج محادثة. Ollama يتحقق من capability completion عبر api/show ويستبعد نماذج التضمين. اختيار ChatModel صراحةً لا يتغير تلقائيًا إلى نموذج آخر إذا كان غير موجود. حالة AI تعرض اسم النموذج المختار، ولا تعتبر خادمًا يحتوي نماذج تضمين فقط جاهزًا للمحادثة.

سكربت scripts/start-reports.ps1 يتحقق من منفذ 5187 قبل البناء. إذا وجدت نسخة من المشروع نفسه، يعرض رابطها؛ ومع -Restart يوقف هذه النسخة ويعيد البناء والتشغيل. لا يوقف عملية تخص برنامجًا آخر. خطأ حجز المنفذ في التشغيل المباشر يظهر الآن برسالة مختصرة. اختبار PowerShell يراجع إعادة استخدام النسخة الشغالة، والتشغيل مجددًا، وحماية عملية غير مرتبطة بالمشروع.

اختبارات إضافية تتحقق من اكتشاف نموذج محادثة، ورفض نموذج مفقود أو خادم تضمين فقط، وLM Studio، وشرح حدود محتوى الوثيقة. اختبار التشغيل يبدأ دون ChatModel ويتحقق من جواب AI في سؤال عد بسيط ومن بقاء البيانات عند تعطل AI.


## عرض جواب النموذج وأزرار الوثائق

جواب النموذج هو النص الرئيسي في المحادثة؛ لا يُسبَق بتقرير ثابت ولا يُضاف كتعليق أسفل جدول backend. المصادر والأعداد المحسوبة تبقى مدخلات موثقة للنموذج. زر فتح وثائق التقرير في Laserfiche ظاهر أعلى الإجابة مع النسخ والتنزيل والطباعة، ويستخدم معرفات الوثائق التي أعادها الخادم فقط. أُزيل زر إلغاء السؤال، وحُفظت ملفات الألوان والخطوط والتخطيط السابقة دون تغيير.
