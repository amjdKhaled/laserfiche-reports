# سلة المحذوفات الحالية

هذا المصدر يعرض **بيانات الوثائق الموجودة حاليًا في السلة**، ولا يسترجع محتوى الملفات ولا يعيدها إلى المستودع. الحذف النهائي لا يمكن جلب محتواه بهذه الأدوات. أحداث الحذف النهائي التاريخية تحتاج مصدر Audit Trail متاحًا؛ وجود حدث حذف لا يعني بقاء الوثيقة في السلة.

## التحديث والإعداد على Windows

1. حدّث الفرع `fix/typed-semantic-repository-plans`، ثم أعد بناء/نشر نسخة Windows وأعد تشغيل التطبيق وReports Graph. تحديث ملفات Python فقط لا يضيف قارئ السلة إلى تثبيت Windows قديم.
2. بناء Web ونشره على Windows يضمان `recycle-bin/LaserficheReports.RecycleBin.exe` مع اعتماداته ورخصة SDK تلقائيًا. يلزم استعادة حزم NuGet أثناء البناء. القارئ مبني x64 على .NET Framework 4.8، باستخدام `Laserfiche.SDK.RepositoryAccess` الإصدار `12.0.2608.7`. يجب توفر متطلبات SDK الرسمية، ومنها .NET Framework 4.8 وVisual C++ 14 x64، وإمكانية اتصال الجهاز بـLaserfiche Server. تحقق من توافق إصدار السيرفر في بيئتك.
3. افتح **الوثائق والنظام ← سلة المحذوفات الحالية**، فعّل الربط، وأدخل اسم Laserfiche Server واسم المستودع الأصليين. هذان اسما اتصال SDK، وقد يختلفان عن عنوان Repository API ومعرّفه. أبقِ الاتصال الآمن مفعّلًا إذا كان السيرفر يدعمه.
4. اضغط **عرض وثائق السلة** للتحقق المباشر دون الاعتماد على نموذج الذكاء الاصطناعي. يمكنك اختيار صفحة أخرى؛ حجم الصفحة 50 وثيقة. بعد نجاح الربط يستطيع المساعد استخدام أداة `recycle_bin` للقائمة أو العدد.

تُحفظ أسماء الربط لكل معرّف مستودع API على حدة، مع دمج الإعدادات دون مسح API أو Audit Trail أو روابط المستودعات الأخرى. لا تُحفظ كلمات مرور جديدة لهذا المصدر؛ القارئ يسجل الدخول بحساب جلسة Laserfiche الحالية، عبر stdin محلي، دون تمرير كلمة المرور في سطر الأوامر أو السجلات. لا يستخدم حساب خدمة بديلًا عند رفض الحساب الحالي. إذا كان حسابك يعمل في API لكنه غير مقبول لاتصال SDK، ستظهر رسالة فشل؛ يجب معالجة اتصال الحساب بالسيرفر.

## نطاق النتائج والحدود

- الصلاحيات التي يطبقها Laserfiche تحدد العناصر المرئية؛ قد يرى المستخدم حذفَه فقط، بينما صاحب امتياز إدارة الوصول يرى نطاقًا أوسع. لا يُدّعى أن النتيجة تشمل حذف جميع المستخدمين.
- تُقرأ عناصر `DeletedEntry` من SDK، وتُستبعد الصفحة أو الملف الإلكتروني المحذوفان من وثيقة باقية. افتراضيًا تعرض الوثائق، ويمكن للأداة طلب المجلدات أو كليهما.
- تُحسب الإجماليات من القراءة المكتملة للنطاق المرئي، ثم تُقسم نتائج العرض إلى صفحات وترتب بتاريخ الحذف. السلة قد تتغير أثناء القراءة؛ التقرير ليس لقطة تاريخية ثابتة. لا توجد روابط فتح وثيقة حية لمعرّفات السلة.
- لا تُفسّر أخطاء الاتصال أو نقص الصلاحيات أو بيانات القراءة غير الصالحة على أنها سلة فارغة. حد القراءة 100,000 صف SDK، وحد الرد 32 مليون حرف، والمهلة ساعة؛ تجاوزها يوقف التقرير دون إعلان إجمالي جزئي.
- يدعم المصدر القائمة والعدد ونوع الإدخال وترقيم الصفحات فقط. شروط الاسم والتاريخ والحقول والمحتوى وغيرها غير المدعومة تُرفض؛ لا تُسقط بصمت ولا تتحول إلى بحث عادي.
- القارئ يحتاج Windows؛ Docker وLinux يظهران سبب عدم توفره. لا توجد محاولة لاختراع REST endpoint للسلة.
- الرد التوضيحي للنموذج محدود بسؤال واحد قصير مع رفض التكرار وإعادة المحاولة مرة واحدة. عدم تهيئة رابط Audit Trail في التطبيق لا يعني تعطيل التدقيق في Laserfiche.

## التحقق المحلي

نجح بناء Release للتطبيق وقارئ SDK، وفحص نسخ القارئ واعتماداته إلى مجلد النشر عند البناء وعند Publish مع NoBuild. نجحت 450 حالة C# عبر منفذ انعكاس محلي (حالة قاعدة بيانات خارجية متجاوزة؛ VSTest غير مستقر في بيئة العمل)، و178 حالة Python منها حالة اختيارية متجاوزة، و26 حالة واجهة. نجح بدء مضيف الويب ورفض طلبات السلة المجهولة برمز401، وفحص واجهة السلة على متصفح بمقاسي 1440×1000 و390×844 باستخدام API محاكاة دون أخطاء JavaScript أو تجاوز عرض الصفحة. لا تتضمن هذه الفحوص اتصال SDK فعليًا بسيرفر Laserfiche.
